### HTML ที่ใช้ได้ (validator จะตรวจ)
`p ul ol li b i u sub sup br table thead tbody tr th td(colspan/rowspan) figure img figcaption h4 h5 small mark span div a`
- `<div class="box">` กรอบเนื้อหา (เช่นกล่อง/ตารางสรุปที่หนังสือตีกรอบไว้) · `<div class="pearl">` จุดสำคัญ/ข้อควรจำ · `<div class="warn">` red flag/อันตราย
- `<div class="tbl"><table>…</table></div>` ตารางทุกตารางให้ห่อด้วย div.tbl (เลื่อนแนวนอนในมือถือได้) ใช้ `<thead><tr><th>` เป็นหัว
- `<span class="hi">` เน้นคำ · `<span class="tag">` ป้ายเล็ก · `<span class="up">↑</span>` `<span class="down">↓</span>`
- รูป: `<figure><img src="symp/img/ch08-f1.webp" alt="คำอธิบายสั้น"><figcaption>รูปที่ 1 …</figcaption></figure>`
- flow: `<div class="flow" data-flow="f1"></div>` วางตรงตำแหน่งที่ควรเห็นใน section ที่เกี่ยวข้อง
- ห้าม `style=`, ห้าม class อื่น, ห้าม h1–h3 (h4/h5 ใช้เป็นหัวข้อย่อยในเนื้อหาได้)

## กติกาเนื้อหา (สำคัญที่สุด)
1. **ครบ 100%**: ทุกข้อเท็จจริงในบทต้องอยู่ — ทุกโรค/สาเหตุ ทุกเกณฑ์ ตัวเลข cut-off ค่า lab ขนาดยา ระยะเวลา %
   ทุกรายการในลิสต์ ทุกแถวของตาราง ทุก classification ทุก mnemonic ทุกเชิงอรรถที่มีเนื้อหา ทุกคำอธิบายรูป
   เขียนแบบ **สรุปอ่านง่าย** (bullet สั้น ๆ ตาราง กล่อง) แทนย่อหน้ายาว — ตัดแค่คำฟุ่มเฟือย ไม่ตัดเนื้อหา
   ถ้าลังเลว่าตัดได้ไหม → เก็บไว้
2. **ตัดออก**: เอกสารอ้างอิง, ชื่อผู้นิพนธ์, วัตถุประสงค์การเรียนรู้, ย่อหน้าเกริ่นนำที่ไม่มีข้อเท็จจริง, ย่อหน้า "สรุป" ท้ายบทที่แค่พูดซ้ำ
   (ถ้าสรุปมีข้อมูลใหม่ให้รวมเข้าหัวข้อที่เกี่ยวข้อง), หัว/ท้ายกระดาษ, เลขหน้า, QR code
3. **ไม่เติมความรู้นอกเล่ม** ไม่แก้ตัวเลขของหนังสือ — ถ้าหนังสือพิมพ์ผิดชัด ๆ ให้คงไว้ตามหนังสือ
4. ภาษา: ไทยตามหนังสือ ศัพท์แพทย์ภาษาอังกฤษคงไว้เป็นอังกฤษ (ไม่แปล) · แก้คำที่ OCR ผิดให้ถูกตามภาพ
5. ตาราง → `<table>` ครบทุกแถวทุกคอลัมน์ (ห้ามแคปตารางเป็นรูปแทน ยกเว้นตารางที่เป็นภาพประกอบจริง ๆ)
6. ตัวอย่างบทสนทนา/ประโยคพูดกับผู้ป่วยในหนังสือ: เก็บไว้ (เป็นเนื้อหา) แต่จัดให้อ่านง่าย

  (ข) แปลงเป็น flow JSON ให้ตรงกับรูปทุกกล่องทุกลูกศรทุก label (`"src": "fig"`)

## Flow diagram (interactive)
- `k` ชนิดกล่อง: `start` จุดเริ่ม/อาการนำ · `q` คำถาม/จุดตัดสินใจ · `act` สิ่งที่ทำ (ซักประวัติ ตรวจ ส่ง lab รักษา) · `dx` การวินิจฉัย/ผลลัพธ์ · `stop` ภาวะเร่งด่วน/ต้องส่งต่อทันที · `note` หมายเหตุ
- `t` ข้อความในกล่อง สั้น (≤ ~80 ตัวอักษร) · `d` (ไม่บังคับ) รายละเอียดเพิ่มที่จะเปิดเมื่อกดกล่อง (HTML) เช่น รายชื่อโรค เกณฑ์ ค่า lab
- `l` บนลูกศร = เงื่อนไข เช่น "ใช่" "ไม่ใช่" "MCV < 80 fL" (ผู้ใช้กดเดินทีละขั้นได้ ป้ายลูกศรจะกลายเป็นปุ่มตัวเลือก — จึงควรมี label ทุกครั้งที่กล่องหนึ่งแตกหลายทาง)
- ต้องเป็นกราฟที่มีทิศทาง ไม่มีวงวน (DAG) ทุกกล่องต้องไปถึงได้จากกล่องเริ่ม · ≤ 60 กล่องต่อ flow (ใหญ่กว่านั้นแยกเป็นหลาย flow)
- นอกจาก flowchart ในรูป: ถ้าเนื้อหาส่วนไหนเป็น **ขั้นตอน approach** ที่อ่านแล้วสรุปเป็น algorithm ได้ (เช่น "แนวทางการวินิจฉัย" แยกตามลักษณะอาการ, แยก acute/chronic, แยกตามผล lab)
  ให้สร้าง flow เพิ่ม (`"src": "text"`) โดยใช้ **เฉพาะเนื้อหาในหนังสือ** ห้ามแต่ง branch เอง · ใส่ `"note"` บอกว่าสร้างจากเนื้อหาหัวข้อไหน
  เนื้อหาเดิมยังต้องอยู่ใน html ครบ (flow เป็นตัวช่วยอ่าน ไม่ใช่ตัวแทน)
- บทที่เป็นอาการ (approach to symptoms) ส่วนใหญ่ควรมีอย่างน้อย 1 flow — บทที่ไม่เหมาะ (เช่น การสื่อสาร) ไม่ต้องฝืน
