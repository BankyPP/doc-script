### แบบ A — หัวข้อที่มีบทคู่ในตำราศิริราช (`target` = เลขบท) → บอกว่าจะ **วางเนื้อหาเล่มเหลืองตรงไหน** ของบทนั้น
```json
{
  "key": "1-1", "en": "Chest pain", "th": "เจ็บหน้าอก", "pdf": "10–11",
  "target": 13,
  "ops": [
    { "op": "sec", "after": "cause", "id": "yb-1-1-approach", "h": "Approach แยก cardiac / non-cardiac", "html": "<div class=\"flow\" data-flow=\"y11a\"></div><ul>…</ul>" },
    { "op": "append", "sec": "cvs-mi", "html": "<ul><li><span class=\"hw\">STEMI → …</span></li></ul>" },
    { "op": "sub", "sec": "resp", "id": "yb-1-1-ptx", "h": "Pneumothorax (โน้ตในเล่มเหลือง)", "html": "…" }
  ],
  "flows": [ { "id": "y11a", "title": "Chest pain — cardiac vs non-cardiac", "src": "fig", "img": "yb-1-1-f1.webp", "nodes": [...], "edges": [...] } ]
}
```
- `append` = ต่อท้ายเนื้อหาของหัวข้อ/หัวข้อย่อย `sec` (id อะไรก็ได้ในบท) — ใช้เมื่อเนื้อหาเล่มเหลืองพูดเรื่องเดียวกับหัวข้อนั้น (เช่น โน้ต STEMI → หัวข้อ myocardial ischemia)
- `sub` = เพิ่มกล่องย่อยใหม่ใต้หัวข้อ `sec` (sec ต้องเป็นชั้นบนสุดหรือชั้นที่ 2) — เรื่องใหม่ที่อยู่ในหมวดนั้น
- `sec` = หัวข้อใหม่ชั้นบนสุด วางหลัง `after` (id ชั้นบนสุด / `"^"` = ไว้หน้าสุด / `null` = ท้ายบท) — ใช้กับ algorithm ภาพรวมของเล่มเหลือง หรือเรื่องที่ไม่มีหัวข้อคู่
- `sub`/`sec` มี `sub` ซ้อนได้ (รวมไม่เกิน 3 ชั้นจากบนสุด) · id ใหม่ทุกตัวขึ้นต้น `yb-<key>-` และห้ามซ้ำ
- **merge ให้จริง**: กระจายเนื้อหาเล่มเหลืองไปอยู่ในหัวข้อที่ตรงเรื่องที่สุดของบทศิริราช (สาเหตุ → หัวข้อสาเหตุนั้น, ลายมือเรื่องโรคหนึ่ง → หัวข้อโรคนั้น)
  algorithm ภาพรวมวางเป็น `sec` ใกล้หัวข้อ approach/สาเหตุ ของบทศิริราช — ไม่ต้องกองทุกอย่างไว้ที่เดียว
- เนื้อหาซ้ำกับตำราศิริราช: **ยังต้องใส่** (เป็นอีกแหล่งหนึ่ง ป้ายจะบอกว่ามาจากเล่มเหลือง) — ห้ามแก้หรือลบเนื้อหาศิริราช
- หลายหัวข้อของเล่มเหลืองชี้บทศิริราชเดียวกันได้ (เช่น 6.4–6.7 → บท 24) — แต่ละหัวข้อเป็นไฟล์ของมันเอง

### แบบ B — หัวข้อที่ไม่มีบทคู่ (`target: null`) → บทใหม่ (เนื้อหาเล่มเหลืองล้วน)
```json
{
  "key": "1-4", "en": "Claudication", "th": "ขาเจ็บเมื่อเดิน (claudication)", "pdf": "15", "target": null,
  "new": { "id": "claudication", "th": "ขาเจ็บเมื่อเดิน", "en": "Claudication", "g": "cvr" },
  "sections": [ { "id": "yb-1-4-approach", "h": "…", "html": "…", "sub": [ … ] } ],
  "flows": [ … ]
}
```
- `g` กลุ่มระบบ: `base` พื้นฐาน · `gen` อาการทั่วไป/ภาวะเร่งด่วน/ไข้ · `neuro` · `cvr` หัวใจ ทรวงอก การหายใจ · `gi` · `heme` · `kub` ไต ทางเดินปัสสาวะ · `msk` กระดูก ข้อ ผิวหนัง (รวม rheumato) · `endo` ต่อมไร้ท่อ
- `new.th` ชื่อไทยสั้น ๆ (ถ้าเล่มไม่มีไทย ตั้งตามคำแพทย์ไทยทั่วไป) · `new.id` ภาษาอังกฤษตัวเล็ก-ขีด ไม่ซ้ำกับบทศิริราช

### HTML ที่ใช้ได้ (vyb.py ตรวจ)
`p ul ol li b i u sub sup br table thead tbody tr th td(colspan/rowspan) figure img figcaption h4 h5 small mark span div a`
- `<div class="box">` กรอบ · `<div class="pearl">` จุดสำคัญ · `<div class="warn">` red flag · `<div class="tbl"><table>…</table></div>` ตารางทุกตาราง
- span: `hi` เน้น · `tag` ป้ายเล็ก · `up` ↑ · `down` ↓ · `en` · `muted` · **`hw` = ลายมือ/โน้ตที่เจ้าของเล่มเขียนเพิ่ม** (ข้อความพิมพ์ในหนังสือไม่ต้องใส่ hw)
- รูป: `<figure><img src="symp/img/yb-1-1-f2.webp" alt="…"><figcaption>…</figcaption></figure>`
- flow: `<div class="flow" data-flow="y11a"></div>` · ห้าม `style=` ห้าม class อื่น ห้าม h1–h3

## กติกาเนื้อหา
1. **ครบ 100%** ทั้งตัวพิมพ์และลายมือ: ทุกกล่องใน algorithm, ทุกโรคในรายการ, ทุกคำอธิบายใต้ภาพ (ย่อหน้าไทยใต้ algorithm), ทุกตาราง, ทุกโน้ตลายมือ
   (ลายมือที่อ่านไม่ออกจริง ๆ → `<span class="hw">[อ่านไม่ออก]</span>` หรือเดาแล้วใส่ `(?)`) — เขียนสรุปอ่านง่าย bullet/ตาราง ไม่ตัดเนื้อหา
2. ตัดออก: เอกสารอ้างอิง, หัวกระดาษ, เลขหน้า · ไฮไลต์/วงสี/ดาวที่ไม่มีข้อความ → ไม่ต้องสนใจ (แต่ถ้าเจ้าของเล่มวง/ไฮไลต์กล่องไหนเด่น ๆ ใส่ `<span class="hi">` ได้)
3. ไม่เติมความรู้นอกเล่ม · ไม่แก้ตัวเลข · ศัพท์อังกฤษสะกดผิดชัด ๆ แก้ได้ · ภาษาไทยตามเล่ม ศัพท์แพทย์อังกฤษคงไว้
4. **ลายมือ**: ใส่ไว้ใกล้สิ่งที่มันอธิบายที่สุด — ถ้าเขียนข้างกล่องใน algorithm → ใส่ใน `d` ของกล่องนั้น (เป็น `<span class="hw">…</span>`) **และ**/หรือ ใน html หัวข้อที่ตรงเรื่อง (ข้อความยาว ๆ เรื่องโรคหนึ่ง → ไปอยู่ในหัวข้อโรคนั้นของบทศิริราชด้วย `append`)
   หน้าลายมือล้วน (เช่น asthma phenotype) → หัวข้อ/กล่องย่อยของมันเอง
5. **หน้าแทรกจากตำราอื่น** (ภาพตารางภาษาอังกฤษ, หน้าหนังสือเล่มอื่นที่ติดมา) → พิมพ์เนื้อหาออกมาเป็นตาราง/ลิสต์ ใส่ `<small>(หน้าแทรกจากตำราอื่นในเล่มเหลือง)</small>` · ภาพประกอบจริง (รูปถ่าย smear, Tanner stage, anatomy) → crop เป็น figure
6. ภาษาไทยในลายมือมักย่อ/เป็นภาษาพูด → พิมพ์ตามที่เขียน (แก้แค่ให้อ่านรู้เรื่อง)

## Flow diagram (interactive) — ทุก algorithm ในเล่มต้องเป็น flow
- แต่ละ algorithm พิมพ์ในเล่ม → (ก) crop ทั้ง algorithm (รวมลายมือรอบ ๆ) ใส่ `img` (ข) แปลงเป็น flow `"src": "fig"` ให้ตรงทุกกล่อง ทุกเส้น ทุก label
- `k`: `start` อาการนำ · `q` คำถาม/จุดตัดสินใจ · `act` สิ่งที่ทำ (ตรวจ/ส่ง lab) · `dx` การวินิจฉัย/กลุ่มโรค · `stop` เร่งด่วน · `note` หมายเหตุ
- `t` ≤ ~80 ตัวอักษร (ยาวกว่านั้นไป `d`) · `d` = รายละเอียดเมื่อกดกล่อง (HTML) — **รายชื่อโรคใต้กล่องใส่ใน `d` เป็น `<ul>`** · ลายมือข้างกล่องใส่ `d` เป็น span.hw
- `l` บนลูกศร = เงื่อนไข (≤ ~40 ตัวอักษร) — กล่องที่แตกหลายทางต้องมี `l` ทุกเส้น (ผู้ใช้กด "ทีละขั้น" แล้วป้ายจะกลายเป็นปุ่มตัวเลือก) · ถ้าในเล่มไม่มีป้าย ให้ใช้ชื่อกล่องปลายทางแบบสั้นเป็น `l`
- กล่องที่เป็นแค่คำตอบ (Yes/No, ↑/↓, positive/negative) → ยุบเป็น `l` บนลูกศร
- DAG ไม่มีวงวน · ทุกกล่องไปถึงได้จากกล่องเริ่ม · ≤ 60 กล่อง/flow (ใหญ่กว่านั้นแยก) · flow id = `y<key ไม่มีขีด><a,b,c…>` เช่น `y11a`, `y95b`, `y310a`
- `title` = ชื่อ algorithm ในเล่ม · `note` (ไม่บังคับ) เช่น "ลายมือเพิ่มกล่อง … เข้าไป"
- algorithm ที่ลายมือเขียนเพิ่ม (ลายมือเป็นกล่อง/ลูกศรใหม่) → ใส่เข้า flow ด้วย และบอกใน `d` ว่าเป็นลายมือ (`<span class="hw">ลายมือ</span>`)
- ข้อความแบบขั้นตอนที่เป็น approach แต่ไม่ได้วาดเป็นแผนผัง (เช่นลายมือเป็นลำดับขั้น) → ทำ flow `"src": "text"` ได้ ถ้าทุกกล่องมีในเล่มจริง
